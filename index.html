A Machine-Learning Approach to Identifying Content Refresh Opportunities

FlyRank ML Internship — Capstone Research Paper

This study evaluates a model for prioritizing content for human review. It does not establish that refreshing content causes better outcomes.

Abstract

This study investigates whether machine learning can help FlyRank prioritize content for editorial review. It uses an anonymized FlyRank ML Internship dataset containing 30,000 content-item rows and 44 columns. A corrected model was evaluated using a client-grouped test split and compared with a majority-class baseline. The model achieved 51.6% accuracy and an F1-score of 0.559, while the baseline achieved 51.1% accuracy and an F1-score of 0.676. These results do not establish an overall improvement over the baseline, so the model should remain an experimental decision-support tool requiring further validation and human review.

1. Introduction

FlyRank's content-refresh problem involves deciding which existing pages deserve attention when reviewers have limited time. Manually reviewing every page can be time-consuming, and performance signals alone do not always explain why a page may be declining. This project explores whether machine learning can use existing content and performance signals to rank items for further investigation.

The models are evaluated against a rule-based baseline using a client-holdout validation strategy. In the reported starter-dataset evaluation, the Random Forest achieved a Precision@50 of 0.740, compared with 0.240 for the baseline rules. This indicates that the model ranked more positive examples near the top of the review queue in this experiment. However, the result does not guarantee performance on new production data or show that refreshing a page causes its performance to improve. The intended use is decision support: human reviewers should check each recommendation and make the final editorial decision.

2. Data

The model report identifies the bundled anonymized starter dataset, data/raw/content_refresh_anonymized.csv, as its source. It contains 30,000 rows, including 16,262 rows labelled as declining (reported rate: 0.542).

The exact date window, source-table lineage, and release details should be verified from the project documentation before publication. The report states that titles, URLs, client names, domains, and keywords are not used by the model.

3. Methodology

The target is is_declining_label. The reported models are Decision Tree, Logistic Regression, and Random Forest, compared with a rule-based baseline. The report identifies the validation strategy as client_holdout. Detailed split configuration and leakage checks should be confirmed against the experiment artifacts.

6. Limitations

  • The results apply to the starter dataset and evaluation documented by the repository.
  • The exact date window and detailed validation configuration require verification.
  • Feature importance indicates model reliance, not causation.
  • Performance on other datasets, clients, or time periods has not been established.
  • The baseline's recall and F1-score were not reported and are not inferred here.

7. Ranked Recommendations

  1. Review high-priority items manually and confirm a genuine issue exists.
  2. Check content accuracy, completeness, freshness, and audience relevance.
  3. Review impressions, clicks, engagement, and position in context.
  4. Investigate technical issues where relevant.
  5. Measure outcomes after approved updates and avoid assuming causation.

These are proposed review actions, not guaranteed outcomes. Human reviewers should approve every action.

8. Reproducibility

The project repository contains the model report, source notebook, and chart artifacts. Before final publication, verify the dataset release, date window, validation details, and source of every metric against the experiment artifacts.
