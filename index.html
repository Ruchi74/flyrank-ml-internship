A Machine-Learning Approach to Identifying Content Refresh Opportunities

FlyRank ML Internship — Capstone Research Paper

This study evaluates a model for prioritizing content for human review. It does not establish that refreshing content causes better outcomes.

Abstract

This study investigates whether machine learning can help FlyRank prioritize content for editorial review. It uses an anonymized dataset containing 30,000 content-item rows. After filtering, 18,010 eligible rows from 30 clients remained. A client-grouped split used 23 clients for training and 7 held-out clients for testing. In a conservative feature sensitivity check, the decision tree achieved 60.3% accuracy, 66.4% precision, 61.4% recall, and an F1-score of 0.638. The majority-class baseline achieved 56.9% accuracy and an F1-score of 0.725. These preliminary results do not demonstrate an overall improvement over the baseline on F1-score. Further feature-timing verification and validation are required before practical use.

1. Introduction

This study explores whether content-performance signals can help prioritize pages for human editorial review. The evaluation uses a client-grouped split, with 23 clients used for training and 7 separate clients held out for testing. The conservative decision tree achieved 60.3% accuracy and an F1-score of 0.638, while the majority-class baseline achieved 56.9% accuracy and an F1-score of 0.725. Although the model achieved higher accuracy and precision, its recall and F1-score were lower than the baseline's. The model should be treated as experimental decision support, with human reviewers verifying recommendations before making editorial changes.

2. Data

This project uses the anonymized FlyRank ML Internship starter dataset containing 30,000 content-item rows and 44 columns. The target identifies content items whose impressions declined by at least 20% compared with the previous 30-day period, among records with at least 100 previous-period impressions.

After filtering, 18,010 rows from 30 eligible clients remained. Two clients had no qualifying records. The dataset's complete collection process and feature measurement windows have not been independently verified, so the findings should be interpreted cautiously.

3. Methodology

The project follows a supervised machine-learning workflow. The decline target is defined using current and previous 30-day impressions. Content identifiers are used for grouping and validation, not as predictive features. A client-grouped split assigns 23 eligible clients to training and 7 separate clients to testing, with no client overlap. Preprocessing is fitted on training data only.

A conservative sensitivity check removes aggregate performance features whose measurement windows may overlap with the target period. The resulting decision tree is compared with a majority-class baseline on the same held-out test set. The remaining features' measurement windows still require verification; therefore, this check does not prove that every feature is leakage-free.

4. Results

The conservative decision tree and majority-class baseline were evaluated on the same held-out test set of 3,465 rows from 7 clients.

Model Accuracy Precision Recall F1-score
Conservative decision tree 60.3% 66.4% 61.4% 0.638
Majority-class baseline 56.9% 56.9% 100.0% 0.725

The conservative model achieved higher accuracy and precision than the baseline, but its recall and F1-score were lower. Its confusion matrix contained 1,210 true positives, 881 true negatives, 612 false positives, and 762 false negatives. The model therefore did not outperform the majority baseline on F1-score. These preliminary results do not establish production readiness.

5. Discussion

The conservative model provides a different precision-recall trade-off from the majority baseline. It identifies some decline cases while avoiding the strategy of predicting every item as declining. However, its F1-score remains below the baseline's, and it misses some actual decline cases. The test set contains only seven held-out clients, so performance on other clients and future data remains uncertain. Human review is required before taking action.

7. Limitations

  • The results apply only to the filtered starter dataset and the client-grouped split used in this experiment.
  • The evaluation includes 23 training clients and 7 held-out clients, limiting confidence about generalization.
  • The timing of remaining feature measurements must be verified to assess possible target leakage.
  • The majority baseline achieved a higher F1-score than the conservative decision tree.
  • Feature importance does not establish causation.
  • Performance on other clients, date ranges, or datasets has not been established.
  • The model is an exploratory decision-support tool, not a proven production solution.

8. Ranked Recommendations

  1. Review high-priority items manually and confirm a genuine issue exists.
  2. Check content accuracy, completeness, freshness, and audience relevance.
  3. Review impressions, clicks, engagement, and position in context.
  4. Investigate technical issues where relevant.
  5. Measure outcomes after approved updates and avoid assuming causation.

These are proposed review actions, not guaranteed outcomes. Human reviewers should approve every action.

9. Reproducibility

The project repository contains the model notebook and supporting artifacts. Before final publication, verify the dataset release, date window, feature timing, validation configuration, and metrics against the final experiment outputs. The reported results refer to the conservative sensitivity-check model and its grouped test split.
